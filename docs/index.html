02   /   DESKTOP LAYOUT

Two ways to frame a workspace

Open the gallery on desktop and choose Split title bar to switch layouts. Select it again to return to the unified bar.

Unified

Run one toolbar across the window. Keep the sidebar button, app name and current document together. This works well for a component browser.

Split

Extend the sidebar surface up to the window controls. Align its trailing edge with the navigation below, then put the document title and actions on the canvas side, as in a conversation workspace.

Build it in GPUI

Keep the layout choice and sidebar visibility in your view. Compose the header from two GPUI divs. In split mode give the leading div the same width and background as the sidebar. Let the document title take the remaining space and truncate when needed.

Use a Jig Button for sidebar visibility and a Toggle for the split layout. Give each an accessible name and a visible keyboard focus style. Collapse the leading section when the sidebar closes. At phone widths, Cratebook uses bottom navigation and keeps the active title in the header.

On macOS, set a transparent native title bar, reserve space for the traffic lights and attach window dragging and double-click behavior to the title area. Keep interactive controls outside the drag region.

03   /   WORKBENCH

A switch in Rust

The view owns the value. GPUI modifiers set the appearance.

use gpui::{prelude::*, *};
use gpui_jig::switch;

struct Settings { notifications: bool }

impl Render for Settings {
    fn render(&mut self, _: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        switch::root("notifications", "Notifications", self.notifications)
            .px_3().py_2().rounded_md()
            .bg(rgb(if self.notifications { 0x20704a } else { 0x404044 }))
            .text_color(rgb(0xffffff))
            .focus_visible(|style| style.underline())
            .on_click(cx.listener(|this, _, _, cx| {
                this.notifications = !this.notifications;
                cx.notify();
            }))
            .child(if self.notifications { "Notifications on" } else { "Notifications off" })
    }
}

Why I’m building this

I started GPUI Jig while building a Rust desktop app in stealth. I meant to ship that app. The more I used it myself, the less sure I was that it was something people would keep coming back to. I still care about how a button feels or how much room a sidebar takes up. Getting those details right leaves a bigger question open: what would someone open the app to do tomorrow?

While I figure out where to take the app next, I’m rewriting the tools I built for it and releasing them as open source. GPUI Jig is one of those tools. If you’re building a different kind of Rust app, I’d like you to be able to take the parts you need and make them feel at home in yours.
